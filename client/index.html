Every wallet starts as a random number. Software cannot make one: a pseudo-random generator is a formula, and whoever learns its starting state can replay every key it will ever produce. That has already cost real money, more than once.

Quantum measurement is different in kind. The outcome of measuring a photon is not hidden in any earlier state, so there is nothing to learn and nothing to replay. VOID takes those measurements and puts them where Web3 can use them.

● 01 · measure
A lab device measures photons

The quantum source returns raw bytes over HTTPS. The node runs frequency, runs, chi-square and correlation tests on what arrives and shows the results in the console.

● 02 · commit
The node commits to its next value

Each round carries the hash of the value the node will contribute to the round after it. Once that hash is public, the node cannot swap the value for a luckier one.

● 03 · mix
Four inputs go into one hash

32 fresh quantum bytes, the committed node value, the latest NIST Randomness Beacon pulse and the latest drand round are hashed together with the previous output using SHA3-512.

● 04 · sign and chain
The output is signed and linked

The node signs the round with its ed25519 key, and each round names the output of the one before it, so history cannot be rewritten without breaking every later round.

● 05 · use
Anyone can build on it

Name a future round and a seed before it exists, then draw from it once it does. Neither you nor the node could have known the result, and everyone can recompute it.

thingspeoplekeepasking
Questions.Answers.
What does Quantum-as-a-Service mean here?

It means the quantum hardware is somebody else's problem and the result is an HTTP call. The node holds the connection to the device, tests what comes out of it, and exposes six services: a public beacon, private entropy, raw quantum bytes, provably fair draws, a circuit simulator and the Key Forge. Any app, on any chain or none, can call it today without a key or an account, and every response says how many fresh quantum bytes went into it.

Is the randomness really quantum?

The raw bytes come from an ID Quantique Quantis quantum random number generator operated by the Laboratory for Digitalisation at OTH Regensburg, which serves them over a public API. The device measures single photons. The console shows every pull from it, the byte counts and the statistical tests the node runs on what arrives. Each beacon round states how many quantum bytes it contains and prints them.

Why mix in NIST and drand if the source is already quantum?

Because a good design does not depend on one party. A quantum source proves the bytes were unpredictable when measured; it does not prove the operator relayed them honestly. The node commits to its own value one round early, then mixes in the NIST Randomness Beacon and drand, which are public, signed and outside its control. The output is unpredictable as long as any one input is.

What can I build with it?

Anything that needs a number nobody could know in advance: raffles and airdrop draws, game loot and matchmaking, validator or committee selection, shuffled mints, tie-breaks. Commit to a future round and a seed, wait for the round, call the draw endpoint, and publish the round number so anyone can recompute it. For secrets such as keys and nonces, use the entropy endpoint, which returns bytes no one else receives.

What does the simulator do?

It runs quantum circuits exactly. You place gates on up to 12 qubits, and the page computes every amplitude and the probability of each outcome. Measuring is the one random step in quantum mechanics, and that step is handed to the node, which draws every shot from quantum entropy and signs the counts. The page then re-derives the same counts from the sampling key, so nothing is taken on trust. It ships with Bell pairs, GHZ states, Grover search and the quantum Fourier transform ready to run.

Does the node see the keys the Key Forge makes?

No. The Forge asks the node for 64 bytes, then hashes them together with 64 bytes from your own device before deriving anything. The node knows only its half. The recovery phrase, the Ethereum and Solana addresses and the post-quantum key pairs are computed in your browser and never sent anywhere. The node signs a receipt for the bytes it gave you, which you can check.

What are the post-quantum keys for?

The Forge also derives an ML-DSA-65 signing key pair and an ML-KEM-768 key pair, the lattice schemes NIST standardised as FIPS 204 and FIPS 203. Chains do not accept them for transactions yet. They are for applications that want quantum-resistant signatures or key exchange today, such as signed messages, encrypted backups and off-chain identity.

What is $VOID?

$VOID is the token of the protocol. It funds the node, the sources and the work on the roadmap: the on-chain feed, additional quantum devices and independent operators. The API is open to use while the network is one node.
